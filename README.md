# Trans-Català Rodes — "Sabies que...?" (Did you know...?)

## Overview

A daily, fully automated trivia feature for the Trans-Català Rodes
website: a rotating "Did you know...?" widget on the homepage, backed
by a permanent, SEO-indexable archive page for every entry ever
published — generated by an LLM, with no manual review required.

The site also uses a lightweight build step so the header, footer,
and shared `<head>` tags (favicon, future metadata) live in one place
and propagate to every page — including the archive, which will
eventually hold hundreds of entries.

- **Live site:** https://tcrsl.github.io/web/
- **Archive:** https://tcrsl.github.io/web/efemerides/
- **Monthly cost:** $0 (GitHub Pages + GitHub Actions + Gemini API free tier)

## Architecture

```
GitHub Actions — "Efemèride diària" (daily cron)
        │
        ▼
scripts/generar-efemeride.mjs ── calls Gemini API
        │
        ▼
data/efemerides.json          (source of truth / history)
        │
        ▼
scripts/build.mjs  ◀──────────────── also triggered by "Reconstruir web"
        │                            (GitHub Actions, on push to
        │                             partials/, index.html,
        │                             avis-legal.html,
        │                             efemerides/_template.html,
        │                             data/efemerides.json)
        ├──▶ index.html, avis-legal.html         (header/footer/head injected)
        ├──▶ efemerides/_template.html-based
        │      efemerides/YYYY-MM-DD.html        (regenerated for every entry)
        └──▶ efemerides/index.html               (full listing rebuilt)

partials/header.html, footer.html, footer-llarg.html, head-extra.html
        │
        └──▶ single source of truth for header/footer/head across the whole site

script.js (homepage) ──▶ fetches data/efemerides.json ──▶ renders today's entry
```

| Component | Role |
|---|---|
| GitHub Pages | Serves the static site directly from the repository. |
| GitHub Actions — `efemeride-diaria.yml` | Runs daily at 05:30 UTC (or manually): generates the day's entry, then rebuilds the site. |
| GitHub Actions — `build.yml` | Runs automatically on push to `partials/`, `index.html`, `avis-legal.html`, `efemerides/_template.html`, or `data/efemerides.json`. Rebuilds and publishes without any manual step. |
| `scripts/generar-efemeride.mjs` | Calls the Gemini API, validates the response, appends it to `data/efemerides.json`. |
| `scripts/build.mjs` | The site's "assembler": injects `partials/header.html`, `partials/footer.html` (or `footer-llarg.html`), and `partials/head-extra.html` into every page, and regenerates **every** archive page plus `efemerides/index.html` from `data/efemerides.json`. |
| `partials/header.html` | Shared `<header>` (nav menu, logo) for the whole site. Edited once, propagates everywhere on the next build. |
| `partials/footer.html` | Short footer (copyright only). Used on `avis-legal.html` and every individual archive entry. |
| `partials/footer-llarg.html` | Long footer (contact, links, map). Used on `index.html` and `efemerides/index.html`. |
| `partials/head-extra.html` | Shared extra `<head>` tags (currently the favicon). Future metadata, `robots`, analytics, etc. go here. |
| `data/efemerides.json` | Full history in JSON — the **source of truth** for the whole archive. Read client-side by `script.js` for the homepage widget, and by `build.mjs` to regenerate every archive HTML page. |
| `efemerides/_template.html` | Placeholder-based template (`{{TITOL}}`, `{{DATA}}`, `{{CATEGORIA}}`, `{{TEXT}}`, `{{TEXT_CURT}}`, `{{FONTS_HTML}}`) plus the `HEADER_START/END`, `FOOTER_START/END`, and `HEAD_EXTRA_START/END` markers that `build.mjs` fills in on every run. |
| `efemerides/YYYY-MM-DD.html` | One indexable, permanent page per day. Fully regenerated on every build. |
| `efemerides/index.html` | Archive listing; `build.mjs` rewrites the whole list from `data/efemerides.json` on every build. |

## Making site-wide changes now (header, footer, favicon, metadata...)

With the templating system, **individual pages no longer need to be
edited one by one**. The flow is always:

1. Edit the relevant file under `partials/` (e.g. `partials/header.html` for the nav menu).
2. `git push`.
3. The `build.yml` workflow triggers automatically, runs `scripts/build.mjs`, and publishes the change across every page — including every archive entry, even with hundreds of them.

To preview the result before pushing, run `node scripts/build.mjs`
locally (requires Node).

**Where to add new metadata** (robots, og:tags, analytics, etc.):
`partials/head-extra.html`. It's the single place to edit; it
propagates to every page the same way the header and footer do.

**Important:** the generated pages (`index.html`, `avis-legal.html`,
`efemerides/*.html`) should **not** be hand-edited in their
header/footer/head-extra sections — any manual change there gets
overwritten on the next build. The only source-of-truth files for
those sections live under `partials/`.

## Why Gemini, and two caveats worth knowing

The project runs on Google's Gemini API free tier (no credit card
required, sufficient for one request/day). Two details matter for
future maintenance:

1. **No live web search.** Gemini's search-grounding tool draws from
   a quota that, in practice, requires billing to be enabled even
   under the "free tier." It was removed. To compensate, the prompt
   explicitly instructs the model to use **only well-established,
   consolidated facts** — the kind found in encyclopedias or
   manufacturer archives — and to discard anything it isn't
   confident about, rather than relying on a citation it can't
   verify.
2. **Model alias, not a pinned version.** The script targets
   `gemini-flash-latest` (Google's official rolling alias) instead of
   a dated model name like `gemini-2.5-flash`. Google retired that
   exact model a few months after release; the alias avoids the
   same breakage recurring silently.

To reinstate live fact-checking later (higher reliability, small
added cost), either enable billing on the Google Cloud project, or
migrate the script to Anthropic's or OpenAI's API with search
grounding.

## Reliability without human review

1. **Only three low-risk categories**, no exceptions: "Curiositat
   tècnica", "Història de la maquinària", "Dada curiosa". No
   regulations, laws, or fines — a minor inaccuracy here carries no
   legal or credibility risk, unlike a misquoted regulation would.
2. **Duplicate avoidance:** the last 40 titles are passed back to the
   model so it doesn't repeat a topic.
3. **Explicit anti-hallucination instruction:** if the model isn't
   confident about a specific detail (year, figure, name), it's told
   to pick a different fact it is confident about. If it lacks a
   real, known source URL, it may cite the source name alone.
4. **Clean HTML escaping:** every value is escaped before being
   inserted into HTML, preventing special characters from breaking
   the page.

No daily review is required, but an occasional glance at
`/efemerides/` is recommended, especially in the first few months.

## On SEO

The homepage widget alone does little for SEO — text that changes
daily at the same URL isn't "new" indexable content, it's content
that replaces the previous version.

What does help is the **archive**: every entry is its own permanent
URL with its own title and meta description, which can rank for
sector-specific searches over time. Frame it to stakeholders as "it
makes the site feel alive from day one, and over months it builds an
archive that attracts organic search" — not as an instant SEO switch.

## Routine maintenance

- **Rotate the `GEMINI_API_KEY` secret:** repository → Settings →
  Secrets and variables → Actions.
- **Check for failed runs:** repository → Actions tab; failed runs
  are marked in red. There are now two workflows to watch:
  "Efemèride diària" and "Reconstruir web".
- **Trigger a manual entry generation:** Actions → "Efemèride diària"
  → "Run workflow".
- **Trigger a manual rebuild** (e.g. after editing a partial without
  waiting for a push-triggered run): Actions → "Reconstruir web" —
  currently only runs on `push`, not `workflow_dispatch`; add that
  trigger to `build.yml` if manual runs are needed.
- **If Google retires the model again** (404/429 errors): check the
  model alias first, and consider enabling billing on the Google
  Cloud project if quota errors persist (see caveats above).
