# Trans-Català Rodes — "Sabies que...?" (Did you know...?)

## Overview

A daily, fully automated trivia feature for the Trans-Català Rodes
website: a rotating "Did you know...?" widget on the homepage, backed
by a permanent, SEO-indexable archive page for every entry ever
published — generated by an LLM, with no manual review required. The
site itself is bilingual (Catalan / Spanish), served as fully static,
independently indexable pages.

- **Live site:** https://transcatalarodes.cat/
- **Spanish version:** https://transcatalarodes.cat/es/
- **Archive (CA):** https://transcatalarodes.cat/efemerides/
- **Archive (ES):** https://transcatalarodes.cat/es/efemerides/
- **Monthly cost:** $0 (GitHub Pages + GitHub Actions + Gemini API free tier)

## Bilingual architecture (CA/ES)

The site is bilingual by folder, not by client-side toggle:

- Catalan pages live at the root (`index.html`, `avis-legal.html`,
  `efemerides/`).
- Spanish pages live under `/es/` (`es/index.html`,
  `es/avis-legal.html`, `es/efemerides/`), as their own
  independently indexable URLs — this matters for SEO, since a
  JS-based language toggle on a single URL is not crawlable as
  separate content the way two real URLs are.
- Shared, language-neutral assets (`style.css`, `script.js`, `img/`,
  `fonts/`, `data/efemerides.json`) are **not** duplicated between CA
  and ES.
- The language switcher is a plain `<a>` link between the CA and ES
  version of the same page (no JavaScript involved).
- Every page carries reciprocal `hreflang` tags pointing to its
  translated counterpart.
- `header-es.html`, `footer-es.html`, `footer-llarg-es.html` and
  `head-extra-es.html` (in `partials/`) are the Spanish equivalents
  of the Catalan partials, filled in by `scripts/build.mjs` the same
  way as the Catalan ones.

## Architecture

```
GitHub Actions (daily cron)
        │
        ▼
scripts/generar-efemeride.mjs ── single call to Gemini API
        │                        (returns titol/text in CA + ES together)
        │
        ├──▶ data/efemerides.json             (source of truth / history)
        ├──▶ efemerides/YYYY-MM-DD.html       (new CA archive page)
        ├──▶ es/efemerides/YYYY-MM-DD.html    (new ES archive page)
        ├──▶ efemerides/index.html            (CA index, new entry prepended)
        └──▶ es/efemerides/index.html         (ES index, new entry prepended)

script.js (homepage) ──▶ fetches data/efemerides.json ──▶ renders today's entry
                          (in whichever language the current page is)
```

A second workflow, `scripts/build.mjs`, keeps `index.html`,
`avis-legal.html` and their Spanish equivalents in sync with the
shared `partials/` (header, footer, extra `<head>` tags) any time
those change, and regenerates the full archive (both languages) plus
`sitemap.xml` from `data/efemerides.json`.

| Component | Role |
|---|---|
| GitHub Pages | Serves the static site directly from the repository, on the custom domain in `CNAME`. |
| GitHub Actions (`.github/workflows/efemeride-diaria.yml`) | Runs daily at 05:30 UTC; generates one new bilingual entry; can also be triggered manually. |
| GitHub Actions (`.github/workflows/build.yml`) | Runs on push to `partials/`, `index.html`, `avis-legal.html`, `efemerides/_template.html` or `data/efemerides.json`; rebuilds every page from the shared partials and regenerates the archive. |
| `scripts/generar-efemeride.mjs` | Calls the Gemini API once per day, gets CA+ES content back in a single response, validates it, writes all outputs below. |
| `scripts/build.mjs` | Injects header/footer/head partials (CA and ES) into every page, and regenerates the full archive + sitemap from `data/efemerides.json`. |
| `data/efemerides.json` | Full history in JSON, shared by both languages; read client-side by `script.js` for the homepage widget. |
| `efemerides/_template.html` / `es/efemerides/_template.html` | Placeholder-based templates (`{{TITOL}}`, `{{DATA}}`, `{{CATEGORIA}}`, `{{TEXT}}`, `{{TEXT_CURT}}`, `{{FONTS_HTML}}`, `{{SLUG}}`) filled in on every run, one per language. |
| `efemerides/YYYY-MM-DD.html` / `es/efemerides/YYYY-MM-DD.html` | One new indexable, permanent page per day, per language. |
| `efemerides/index.html` / `es/efemerides/index.html` | Archive listings; new entries are prepended automatically, per language. |

## Why Gemini, and what matters for maintenance

The project runs on Google's Gemini API free tier (no credit card
required, sufficient for one request/day). Two details matter for
future maintenance:

1. **No live web search.** Gemini's search-grounding tool draws from
   a quota that, in practice, requires billing to be enabled even
   under the "free tier." It was removed. To compensate, the prompt
   explicitly instructs the model to use **only well-established,
   consolidated facts** — the kind found in encyclopedias or
   manufacturer archives — and to discard anything it isn't
   confident about, rather than relying on a citation it can't
   verify.
2. **A short fallback list of stable models, not a rolling alias.**
   The script does not target `gemini-flash-latest`. See the
   incident notes below for why, and the current list in use.

To reinstate live fact-checking later (higher reliability, small
added cost), either enable billing on the Google Cloud project, or
migrate the script to Anthropic's or OpenAI's API with search
grounding.

## Model reliability incident (August 2026) and the fix

**Symptom:** the daily GitHub Action started failing two days in a
row with repeated errors from the Gemini API, regardless of the time
of day it ran.

**Root cause:** the script targeted `gemini-flash-latest`. Per
Google's own documentation, this is a *rolling alias* that points to
an **experimental** model with intentionally restrictive rate limits
— it's meant for gathering feedback on Google's newest updates, not
for unattended production use. That's a permanent property of the
alias, not a temporary outage, so waiting it out was not expected to
help.

**Fix applied in `scripts/generar-efemeride.mjs`:**

- Replaced the single `MODEL` constant with a `MODELS_FALLBACK` array
  of three **stable**, free-tier-eligible models, tried in order:
  `gemini-3.1-flash-lite` → `gemini-3.5-flash` → `gemini-3.6-flash`.
- `cridarGeminiAmbReintents()` now loops over that list. For each
  model it allows a couple of quick retries (5s, 10s backoff) on
  *transient* errors (HTTP 429/500/503/504, `RESOURCE_EXHAUSTED`,
  `FAILED_PRECONDITION`, `UNAVAILABLE`), then moves on to the next
  model instead of hammering the same one.
- *Definitive* errors (invalid API key, prompt blocked by safety
  filters, etc.) are thrown immediately — retrying or switching
  models wouldn't fix those, so we don't waste the run's time on
  them.
- The backoff was kept short on purpose (seconds, not minutes) so a
  full run — worst case, all three models failing — still finishes
  well within the GitHub Actions runner's time budget.

**If this happens again:** check
[ai.google.dev/gemini-api/docs/models](https://ai.google.dev/gemini-api/docs/models)
for the current stable model list before touching the code. Update
`MODELS_FALLBACK` with whichever stable Flash-tier models are current,
and avoid anything ending in `-preview` or `-latest` for this
unattended, no-review pipeline — those are explicitly the ones Google
warns are subject to change or come with reduced quotas.

## Reliability without human review

1. **Only three low-risk categories**, no exceptions: "Curiositat
   tècnica", "Història de la maquinària", "Dada curiosa" (stored as a
   fixed identifier, e.g. `curiositat-tecnica`, and localized to CA
   or ES at render time). No regulations, laws, or fines — a minor
   inaccuracy here carries no legal or credibility risk, unlike a
   misquoted regulation would.
2. **Duplicate avoidance:** the last 40 titles are passed back to the
   model so it doesn't repeat a topic.
3. **Explicit anti-hallucination instruction:** if the model isn't
   confident about a specific detail (year, figure, name), it's told
   to pick a different fact it is confident about. If it lacks a
   real, known source URL, it may cite the source name alone.
4. **Clean HTML escaping:** every value is escaped before being
   inserted into HTML, preventing special characters from breaking
   the page.
5. **Model fallback:** three stable models are tried in order before
   the run gives up — see the incident notes above.
6. **Single-call bilingual generation:** Gemini returns the Catalan
   and Spanish title/text together in one JSON response, instead of
   two separate calls — halves API usage and keeps both language
   versions consistent with each other.

No daily review is required, but an occasional glance at
`/efemerides/` and `/es/efemerides/` is recommended, especially in
the first few months.

## On SEO

The homepage widget alone does little for SEO — text that changes
daily at the same URL isn't "new" indexable content, it's content
that replaces the previous version.

What does help is the **archive**, in both languages: every entry is
its own permanent URL with its own title and meta description, which
can rank for sector-specific searches over time. The `/es/` structure
adds a second, fully independent set of indexable URLs rather than
relying on a JS toggle Google can't crawl as separate content. Frame
it to stakeholders as "it makes the site feel alive from day one, and
over months it builds an archive that attracts organic search" — not
as an instant SEO switch.

## Routine maintenance

- **Rotate the `GEMINI_API_KEY` secret:** repository → Settings →
  Secrets and variables → Actions.
- **Check for failed runs:** repository → Actions tab; failed runs
  are marked in red.
- **Trigger a manual run:** Actions → "Efemèride diària" → "Run
  workflow".
- **Editing shared header/footer/head content:** edit the relevant
  file in `partials/` (and its `-es` counterpart if the change should
  also apply in Spanish), then either push (the `build.yml` workflow
  rebuilds automatically) or run `node scripts/build.mjs` locally.
- **If Gemini requests start failing again** (404/429/503 errors on
  all models): first check
  [ai.google.dev/gemini-api/docs/models](https://ai.google.dev/gemini-api/docs/models)
  for the current stable model list, then update the
  `MODELS_FALLBACK` array in `scripts/generar-efemeride.mjs`
  accordingly (see the incident notes above). Only as a last resort
  consider enabling billing on the Google Cloud project.
